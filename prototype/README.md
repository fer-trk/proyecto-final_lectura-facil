# UniLecta · Simulación conceptual

**UniLecta** reúne tres ideas: **Universal, Lectura y Accesible**. Su propósito es reducir barreras para comprender documentos sin limitar el proyecto a la simplificación de textos. El nombre es breve, fácil de pronunciar y permite ampliar la plataforma a otras formas de accesibilidad. La accesibilidad debe formar parte del contenido desde el principio.

Abre `index.html` en un navegador. No necesita instalación ni conexión a Internet.

Esta versión muestra el recorrido que queremos discutir:

1. Adjuntar un documento Word, PDF o TXT. TXT se presenta como **texto sin formato**.
2. Elegir una o más tareas: revisar el original, adaptar a lectura fácil y ver los cambios en detalle. Esta última opción solo está disponible si se elige adaptar.
3. Elegir un grado de adaptación solo cuando corresponda. El género del texto no se pregunta a la persona.
4. Ver qué etapa está en curso mientras se preparan los resultados.
5. Recibir solo los resultados elegidos. Conservar la identidad y estructura originales cuando no supongan barreras de accesibilidad; registrar las modificaciones necesarias.

**Es una simulación, no un procesador de documentos.** El selector de archivos no lee ni envía el contenido. Las etapas de espera, el resultado, la auditoría y el informe de cambios son ejemplos fijos. Solo el archivo HTML de demostración se genera realmente para descargarlo. No hay extracción de Word/PDF/TXT, clasificación automática, adaptación con IA, comprobación automática de fidelidad ni validación de lectura fácil.

## Preguntas para revisar juntas

- ¿El recorrido de adjuntar y descargar refleja la tarea principal?
- ¿Son comprensibles las tres opciones y la dependencia del informe de cambios?
- ¿Los mensajes de espera reducen la incertidumbre o necesitan más información?
- ¿Qué debe conservarse del diseño original y qué puede cambiarse por accesibilidad?
- ¿En qué formato debe salir cada entrada: el mismo formato siempre, o un formato accesible común?
- ¿Qué hallazgos de auditoría son útiles y cuáles generan ruido?

La accesibilidad del prototipo requiere comprobaciones manuales con teclado, zoom y lector de pantalla. No se declara conformidad WCAG ni accesibilidad «al 100 %» sin esas pruebas.
